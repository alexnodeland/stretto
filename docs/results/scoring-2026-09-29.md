# Scored as τ²-bench scores: every check in the reward basis

Every live page so far has reported τ²-bench's database check. τ²-bench's own reward is the product of every check in the task's reward basis ([#12](https://github.com/alexnodeland/stretto/issues/12)). In airline that adds a communication check, a string match that needs no judge. Scored with it, every airline episode kept its reward ([the airline pilot](pilot-airline-2026-09-24.md)). In retail, 39 of the 40 test tasks also count natural-language assertions, and 11 of those have assertions to check. An LLM judges them, for example "Agent should tell the user the camera costs $481.50." A flow changes what the agent reads, so it could change what the agent tells the customer, and the database check would not see it.

This page scores all 1,101 published τ²-bench episodes, from twelve archives, with every check in the basis. Claude Haiku 4.5 judged the assertions three times, and the majority of its three verdicts decides.

## Findings

- **18 of the 1,101 episodes change, all from passed to failed, and 17 of them on one task.**
  - Retail task 68's customer asks what they paid for their most recent order. The orders carry no dates, so the agents often list every order's total.
  - Its one assertion is "Agent should tell the user the order total is $829.43." When the agent names $829.43 among the other totals, the verdict turns on whether that counts as telling it.
  - The judge failed 17 of the 35 task-68 episodes, every one of which had passed the database check. Task 68 is the only task where the judge wavered: on every other episode it gave the same verdict all three times.
  - The eighteenth is a Claude Haiku 4.5 episode of task 108. It told the customer a refund of $347.93, where the items came to $346.93.
- **The full reward costs arms with a flow and without one alike.** 9 of the 18 are in arms with a flow and 9 in arms without. On task 68, episodes with a flow passed the assertion 11 times in 19, and episodes without one 7 times in 16.
- **No comparison changes direction.**
  - *The paired run.* Over its 80 pairs, 70 passed in each arm: 0.0 points (−7.5 to +7.5). The database check had 71 without the flow and 70 with it (−1.25 points, −7.5 to +6.25). Retail's loss narrows from −7.5 points (−17.5 to 0.0) to −5.0 (−15.0 to +5.0). Airline is unchanged.
  - *The frontier run.* With the flow, Claude Sonnet 5 passed 67 of 84, against 64 without it (65 → 69 by the database check). Claude Haiku 4.5 passed 61 against 57 (58 → 62). As before, no comparison's pass-rate interval lies below zero.
  - *The reach round.* GLM-5.3 on its 28 tasks passed 23, 21 and 20 without a flow, with D0 and with the reach flow (24, 21 and 21).
- **Airline, telecom and every other task do not move.** Airline's and telecom's bases need no judge. The solo telecom episodes were already scored with every check, as τ²-bench scores solo mode.
- **The database check reproduces.** Rescored with the database check alone, all 1,101 episodes get the reward they recorded.

## The judge

- **Model.** Claude Haiku 4.5 (`claude-haiku-4-5`), in Claude Code on the Claude subscription, one turn with no tools ([`pilot/judge.py`](../../pilot/judge.py), through [`claude-agent.sh`](../../pilot/claude-agent.sh)). τ²-bench's default judge is GPT-4.1, whose key we do not have.
- **Prompt and rule.** Both are τ²-bench's own. The judge sees the conversation and the assertions and says of each whether it was met. The reward is 0 unless every assertion was met.
- **Three judgings.** 212 episodes had assertions to judge, from 13 retail tasks (the 11 test tasks and two training tasks the cold start recorded). Each was judged three times.
  - The reward was the same all three times in 204 of the 212 episodes, and each assertion's verdict in 300 of 308. All eight episodes that varied are task 68's.
  - The majority of the three decides. With three judgings there are no ties.
- **The result depends on the judge.** Another judge may read task 68 otherwise. The rows hold each judging's verdicts and, where one found an assertion unmet, its reason.

## The harness

- `pilot/run_episode.py` records both rewards. `reward` is the database check, as before. `reward_basis` is τ²-bench's own reward: for a task whose basis has natural-language assertions, `--judge claude:MODEL` judges them, and without a judge the field is empty. `result.json` also lists the assertions and the verdicts. `pilot/run_paired.py --judge` passes the option on to each episode.
- `pilot/rescore.py --scoring basis --judge claude:MODEL` rescores recorded episodes the same way. Solo telecom episodes are scored in solo mode, as they ran.
- [`scripts/basis_report.py`](../../scripts/basis_report.py) combines the judgings by majority and writes the rows.
- `pilot/analyze_paired.py pairs --basis` and `pilot/analyze_trials.py --basis` report passes under every check, from those rows.

## Reproduce

No key but Claude Code's own, for the judge. Unpack each archive in `docs/results/*-episodes.tar.*` into its own folder. Then, for each archive `A`:

```sh
python pilot/rescore.py --scoring basis --judge claude:claude-haiku-4-5 --json A.json \
  $(find A -name simulation.json -printf '%h\n')
```

Judge the episodes with assertions twice more, into `judging-2.json` and `judging-3.json`. They are the rows of the files above whose `nl_assertions` is not empty. Then:

```sh
python scripts/basis_report.py --archive *-episodes.json --extra judging-2.json judging-3.json \
  --rows scoring-2026-09-29.json
python pilot/analyze_paired.py pairs paired-2026-09-25-episodes/retail retail 1 --basis scoring-2026-09-29.json
python pilot/analyze_paired.py pairs paired-2026-09-25-episodes/airline airline 2 --basis scoring-2026-09-29.json
python pilot/analyze_paired.py pool paired-2026-09-25-episodes/retail paired-2026-09-25-episodes/airline
python pilot/analyze_trials.py frontier-2026-09-27-episodes/sonnet --basis scoring-2026-09-29.json --markdown
python pilot/analyze_trials.py frontier-2026-09-27-episodes/haiku --basis scoring-2026-09-29.json --markdown
```

`rescore.py --scoring env` on the same episodes reproduces every recorded reward.

[scoring-2026-09-29.json](scoring-2026-09-29.json) holds a row per episode. Each row has the episode's path in its archive, the recorded reward (`database`), each judging's reward, and the majority (`basis`). It also has each assertion with every judging's verdict and, where a judging found the assertion unmet, that judging's reason.
