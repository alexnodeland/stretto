# Reading "New York" as JFK: the stop after the described record, without a model

[What is left of the detours](detours-2026-09-26.md) ended on a semantic stop. Once Claude Sonnet 4.5 has read the reservation the customer described, it reads no more, and a flow that reads on makes detours: 20 on its airline test episodes, against 7 lookups it used. The binding already scores that stop where the description is an exact value, such as a ticket's phone number (`bindings.described_read`). Airline customers name cities, though, and a reservation holds airport codes. That is language, and [#39](https://github.com/alexnodeland/stretto/issues/39) asked whether it could be read without a model.

It can. τ²-bench's airline server lists its airports with their cities (`list_all_airports`), and one training episode that calls it is enough to learn all twenty: Sonnet's and GLM-5's each have one. A flow can learn that table as aliases and read "from New York to Seattle" as the reservation from `JFK` to `SEA`. But no agent's own training episodes teach the stop. The agents that call every reservation in one turn never reach it. Sonnet, which reads them one at a time, read on after the described one in 13 of 29 places in training (12 of them in one task), where it stopped in 12 of 14 in test. A flow pooled from other agents learns the stop, and cuts 8 of Sonnet's detours, but costs GLM-5 4 of its 55 turns saved. By #39's own bar, which is to cut Sonnet's detours without costing GLM-5's savings, it does not ship.

## The change, as tested

The experiment is commit [2c7ae38](https://github.com/alexnodeland/stretto/commit/2c7ae38) on the branch `flows/aliases`, not merged:

- `learn` reads every list of at least three records of the same two string fields in a training result as a table, and each value's aliases as the other values of its row (`bindings.aliases`).
- A reservation read so far is the one the customer described when the customer said two of its table values, each itself or by an alias, as words: `sea` is not read in "research". Where only that one record has been read, that is enough. Where others have, another must not hold both.
- `described_read` then counts, as it does for exact values, how often the agent went on to read another record of the list in that position. The flow serves that chance there.

A single named city was tried first, and was not enough. In Sonnet's training episodes, after a reservation holding one city the customer named, it read on in 35 of 43 places.

## Replays

Each agent's own flow is learned from its training-task episodes, on the habit alone at 0.3. Each is replayed on its 80 airline test-task episodes (four trials), without the aliases and with them. The figures are turns saved · detours.

## Why no agent's own flow learns it

`detours.py stops` counts, in an agent's own episodes, each reservation read that leaves one of the account's reservations not yet called, and whether the agent goes on to read another before its next other call. It counts them by what the reservations read so far hold (*cities*: one's origin and destination named, by code or city). Places where the customer gave a reservation's id are left out, since the flow scores those apart ([`named_other`](named-other-2026-09-26.md)).

| Agent | Training: reads on · stops | Test |
|---|---|---|
| Claude Sonnet 4.5 | 13 · 16 | 2 · 12 |
| Qwen 3.5 | 31 · 9 | 35 · 3 |
| GPT-5.2 (high) | 2 · 2 | 0 · 1 |
| GPT-5.2 (none) | 2 · 0 | 0 · 0 |
| GLM-5, Claude Opus 4.5 | none: they call every reservation in one turn | none |
| Gemini Flash, Gemini Pro, Qwen3-max | 7 · 7, 13 · 3, 15 · 13 | – |

- **Parallel readers.** GLM-5 and Opus call every reservation at once, and GPT-5.2 nearly so. Their flows learn to read them all, which they then use. GPT-5.2 (high)'s 74 detours are flight-status lookups; on reservations its flow makes 4, against 168 used.
- **Sonnet.** It reads one reservation at a time, and in test it stops where the stop would pay. In training it reads on in 13 of those 29 places, 12 of them in task 27. There the customer's account holds nine reservations and Sonnet reads them all, in every trial. So the chance its own flow learns there stays above the threshold, and the flow reads on as before.
- **Qwen 3.5** reads on.
- **The pool.** The flow counts each record it would read next once per episode, and as used if the agent read it at any point later. By that count the three agents went on to read 16 of 42, so the pooled flow learns the stop. It then serves the stop to the agents that read on too.

## What this leaves

The stop Sonnet makes in its test episodes is real, but its training episodes do not show it reliably, and the other agents either never reach that place or read on. Reading the customer's cities is not what is missing. A stop learned per agent needs more of that agent's episodes in which the described record is found early. A stop learned from a pool helps the agents that stop only at the expense of those that read on.

With [the question to Jev](detours-2026-09-26.md#a-question-for-the-stop-fitted-on-the-agents-own-steps), which was not kept, and the exact-value stop, which [halved the solo telecom flow's detours](telecom-flows-2026-09-26.md#when-the-agent-holds-the-phone), this measures each way #39 proposed.

## Reproduce

```sh
git checkout 2c7ae38    # the experiment; main learns no aliases
cargo build --release -p stretto-report
stretto learn --results claude-sonnet-4-5_enabled_airline_gpt-5.2_4trials.json --tau2 ../tau2-bench \
  --domain airline --habit-only --out sonnet.flow.json
cd pilot && python check_flow_tagged.py --results ../claude-sonnet-4-5_enabled_airline_gpt-5.2_4trials.json \
  --trials 0 1 2 3 --domain airline --flow ../sonnet.flow.json --flow-decider habit \
  --flow-threshold 0.3 --oracle-cache ../.oracle-cache --in-process --jobs 4
cd .. && python3 scripts/detours.py stops claude-sonnet-4-5_enabled_airline_gpt-5.2_4trials.json \
  --split train --tau2 ../tau2-bench
```

The pooled flow takes `--results` once per agent: `geminiflash-airline.json`, `geminipro-airline.json` and Qwen3-max's `airline_llm_agent_qwen3-max-2025-10-30_user_simulator_gpt-4.1-2025-04-14.json`. The rows without aliases are the same commands on main (18007b1). No model was asked.
