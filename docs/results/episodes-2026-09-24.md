# Recorded episodes, 2026-09-24: the live pilots

Every live episode behind the pilot pages is published here: 76 episodes, 40 in retail and 36 in airline. GLM-5.3 in Claude Code was the agent and GLM-5.3 the simulated customer, on τ²-bench's tools served over MCP behind `stretto-proxy`. With these files, anyone can:

- rescore an episode with τ²-bench's own evaluator;
- read what the agent and the customer said, and what the flow looked up;
- audit a flow on the recorded sessions;
- learn the cold start's live flow again.

The customers are τ²-bench's synthetic users.

## What each episode holds

Each archive unpacks to `<archive>/<arm>/task-<id>/`:

| File | What it is |
|---|---|
| `simulation.json` | τ²-bench's `SimulationRun`: every message of the conversation, the termination reason and the reward the pilot recorded. This is what τ²-bench's evaluator reads |
| `result.json` | The pilot's summary: reward, LLM turns, tool calls, parallel turns, the flow's lookups and queries, and the token usage of the agent and the customer |
| `trajectory.jsonl` | The same conversation as `tau2_mcp.py` and `run_episode.py` appended it, one τ²-bench message per line |
| `log/*.jsonl` | `stretto-proxy`'s session log: every MCP message between Claude Code and the tool server (format in [the proxy's README](../../crates/stretto-proxy/README.md#log-format)) |
| `flow.jsonl` | Flow arms only: each decision `stretto flow-serve` made, with the arbiter's probabilities, the System-One answers and the lookup it took |
| `context.jsonl` | The guards arm and the cold start's recorded sessions only: the conversation, as the harness handed it to the proxy |
| `tools-state.json` | The tool server's counts at the end: the agent's tool calls, and the flow's queries and lookups |

Left out are Claude Code's own event streams and configuration, about 26 MB, and the flow server's diagnostics. The pages' LLM-turn counts came from the event streams, and each `result.json` keeps the counts.

The cold-start archive also holds the two files its flow was learned with: `retail-manifest.json`, the tool manifest from τ²-bench's `tools.py` (the same one every compiled retail flow carries), and `rewards.json`, which marks the five recorded sessions as passed.

## Reproduce

**Rescore every episode.** `pilot/rescore.py` scores each `simulation.json` again with τ²-bench's evaluator, in the Python environment the pilots use (see [`pilot/README.md`](../../pilot/README.md)). With `--scoring env`, the database check the pilots used, it reproduces all 76 recorded rewards:

```sh
mkdir -p /tmp/episodes && for a in docs/results/*-episodes.tar.gz; do tar -xzf "$a" -C /tmp/episodes; done
cd pilot && python rescore.py /tmp/episodes/*/* /tmp/episodes/pilot-2026-09-24-episodes/smoke/*
# 76 episodes rescored; 0 differ from the recorded reward
```

`--scoring communicate` and `--scoring basis` apply τ²-bench's other checks (see [#12](https://github.com/alexnodeland/stretto/issues/12)). `basis` skips tasks whose reward counts natural-language assertions unless `--allow-judge` is given, since those need an LLM judge.

**Learn the cold start's live flow again.** Put the five recorded sessions' logs in one directory and run `learn` with the archive's manifest and rewards. With the [answer bundle](answers-2026-09-24-cold-manifest-match.md) imported, every question comes from the cache:

```sh
mkdir -p /tmp/sessions && cp /tmp/episodes/cold-start-2026-09-24-episodes/recorded/*/log/*.jsonl /tmp/sessions/
stretto learn --sessions /tmp/sessions --domain retail \
  --manifest /tmp/episodes/cold-start-2026-09-24-episodes/retail-manifest.json \
  --rewards /tmp/episodes/cold-start-2026-09-24-episodes/rewards.json \
  --predicates data/predicates-v2.json --oracle replay --out cold-live.flow.json
```

The result matches [cold-start-2026-09-24-live.flow.json](cold-start-2026-09-24-live.flow.json) in every field but its compile time.

**Audit a flow on the recorded sessions.** `stretto audit --sessions` reads the same proxy logs.
