# Phase 0 results: τ²-bench, 2026-09-23

**Data.** τ²-bench's published baseline trajectories:

- airline and retail;
- four agent models (Claude 3.7 Sonnet, GPT-4.1, GPT-4.1-mini, o4-mini), with GPT-4.1 simulating the user;
- 4 trials per task, 2,624 episodes in all.

**Method.**

- **The habit** is a hierarchical Dirichlet back-off model of the agent's next action (a tool, or a reply to the user), given the last *k* steps and whether each worked. Its concentration comes from a fugue MH posterior.
- **Training and testing.** It learns from successful episodes on τ²-bench's official training tasks, and is scored on the held-out test tasks.
- **No content yet.** Nothing here looks at *what* the user said or the tools returned. That is Phase 0b's job, with Jev.

Reproduce with:

```bash
cargo run --release -p stretto-report -- phase0 --tau2 ../tau2-bench --out reports/phase0.md
```

## What we learned

1. **About a quarter of LLM turns can be removed by macro-tools, at most.**
   - Runs of consecutive tool calls with no message to the user account for 24% (retail) and 25% (airline) of all LLM turns beyond each run's first call. That is the ceiling for `plan_*` macro-tools.
   - It varies a lot by model. Claude 3.7 Sonnet chains the most tool calls (35% in retail, 41% in airline); GPT-4.1-mini the fewest (13%, 11%).
2. **Arguments can mostly be bound, not generated.**
   - Identifiers, item ids, payment methods and flights in write calls almost always appear verbatim in an earlier tool output or user message.
   - What agents do generate falls into three groups:
     - closed-set choices (41% of retail cancellation reasons, 24% of airline flight types), which suit a Jev `Choice`;
     - arithmetic (certificate amounts, `calculate` expressions), which belongs in code;
     - free text (transfer summaries), which stays with the LLM.
   - The decision to compile arguments from dataflow holds up.
3. **A habit that sees only the tool sequence is weak exactly where flows need it.**
   - Pooled across models at k = 2, the habit predicts the next action at 1.8 bits/step (retail) and 2.2 (airline), with top-1 of 59% and 52%.
   - Split by where the decision is made:
     - **Right after the user speaks** (43–46% of decisions), it can act on 18–23% of them at τ = 0.8, with 92–99% agreement. Common openings like "identify the user" are predictable.
     - **Right after a tool returns** (54–57% of decisions), it can act on only 6–8%.
   - Whether a run continues, and with which tool, depends on what the tool returned. The habit cannot see that; a System-One question over the tool output can. This is the strongest argument in the data for putting Jev inside flows.
4. **Behavior transfers across models.**
   - A habit learned from one model predicts another's held-out behavior within about 3 points of top-1 (airline: 50% against 53%) to 7 points (retail: 55% against 61%) of that model's own habit.
   - That supports the transfer-first plan: compile from one model's traces, and run with another.
5. **Confirmation before writes is mostly followed, but not always.**
   - The user's latest message before a write contains "yes" 87–93% of the time in retail and 66–85% in airline.
   - Counting assent phrases like "go ahead", it is 91–96% and 85–98%.
   - The gap between the two proxies is what a Jev `Noul` ("did the user explicitly confirm this action?") should settle. What remains after that is a baseline violation rate that plan/commit should drive to zero.

## Caveats

- **Old models.** The published baselines are mid-2025 models. Our live runs (GLM, MiniMax) will differ.
- **Agreement is not correctness.** It measures how often the habit matches the agent, and the agent fails 21–50% of tasks.
- **Headroom is an upper bound.** It assumes the agent adopts macro-tools, and that every branch inside a run resolves without a pause.
- **Provenance and confirmation are text-matching heuristics.** Both are labeled as such in the report.

## Next: Phase 0b (replayed shadow mode)

- **What.** Ask Jev at each of the 12,861 held-out decisions (7,115 of them right after a tool returned). Use a `Choice` over the exposed tools plus "respond"; the state is the last user message, the last tool output, and recent actions.
- **Measure.**
  - Agreement with the agent, and calibration.
  - Arbitration: habit first, Jev where the habit is unsure.
  - The four in-flow roles, on the decisions where each one applies.
- **Cost.** About $1.60 at 3k tokens per call, cached so it is paid for once.

### Reading the numbers

- **Bits/step** is the cross-entropy of the agent's actual next action under the habit: 0 means perfectly predictable. **Top-1** is how often the habit's first choice is what the agent did. Actions are tools plus `respond` (a message to the user).
- **Coverage @ τ** is the share of held-out decisions where the habit's top option has probability ≥ τ; **agree** is how often that option matched the agent there. Agreeing with the agent is not the same as being right: the agent fails some tasks.
- **Macro-tool headroom** is Σ(n − 1) over runs of n consecutive tool-calling LLM turns, as a share of all LLM turns: an upper bound on the turns `plan_*` macro-tools could remove.
- **Argument provenance** looks each argument value up, verbatim and lower-cased, in what the user had said and in earlier tool outputs. *Generated* values appear in neither, so the agent had to produce them. *Short* values (< 3 characters) are not attributed.
- **Writes after "yes" / any assent** look at the user's most recent message before each write call: the strict proxy needs the word "yes", the lenient one also accepts phrases like "go ahead" or "proceed". The true confirmation rate lies between them; the System-One question "did the user explicitly confirm?" will measure it.
