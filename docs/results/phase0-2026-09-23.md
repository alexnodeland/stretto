# Phase 0 results: τ²-bench, 2026-09-23

**Data.** τ²-bench's published baseline trajectories:

- airline and retail;
- four agent models (Claude 3.7 Sonnet, GPT-4.1, GPT-4.1-mini, o4-mini), with GPT-4.1 simulating the user;
- 4 trials per task, 2,624 episodes in all.

**Transfer target.** GLM-5 (Z.ai, thinking enabled), from Sierra's τ²-bench leaderboard submission:

- 656 episodes (456 retail, 200 airline), 4 trials per task, with GPT-5.2 simulating the user;
- nothing is learned from it: habit, code features, closed argument sets and validated contexts all come from the four models above;
- it stands in for the first live runs, which use GLM and MiniMax. MiniMax has no public τ²-bench trajectories yet.

**Method.**

- **The habit** is a hierarchical Dirichlet back-off model of the agent's next action (a tool, or a reply to the user), given the last *k* steps and whether each worked. Its concentration comes from a fugue MH posterior.
- **Training and testing.** It learns from successful episodes on τ²-bench's official training tasks, and is scored on the held-out test tasks.
- **No content yet.** Nothing here looks at *what* the user said or the tools returned. That is Phase 0b's job, with Jev.

Reproduce with:

```bash
scripts/fetch-targets.sh   # GLM-5's published trajectories, about 54 MB
cargo run --release -p stretto-report -- phase0 --tau2 ../tau2-bench \
  $(scripts/fetch-targets.sh | sed 's/^/--target /') --out reports/phase0.md
```

## What we learned

1. **About a quarter of LLM turns can be removed by macro-tools, at most.**
   - Runs of consecutive tool calls with no message to the user account for 24% (retail) and 25% (airline) of all LLM turns beyond each run's first call. That is the ceiling for `plan_*` macro-tools.
   - It varies a lot by model. Claude 3.7 Sonnet chains the most tool calls (35% in retail, 41% in airline); GPT-4.1-mini the fewest (13%, 11%).
2. **Arguments can mostly be bound, not generated.**
   - Identifiers, item ids, payment methods and flights in write calls almost always appear verbatim in an earlier tool output or user message.
   - What agents do generate falls into three groups:
     - closed-set choices (41% of retail cancellation reasons, 24% of airline flight types), which suit a Jev `Choice`;
     - arithmetic (certificate amounts, `calculate` expressions), which belongs in code;
     - free text (transfer summaries), which stays with the LLM.
   - The decision to compile arguments from dataflow holds up.
3. **A habit that sees only the tool sequence is weak exactly where flows need it.**
   - Pooled across models at k = 2, the habit predicts the next action at 1.8 bits/step (retail) and 2.2 (airline), with top-1 of 59% and 52%.
   - Split by where the decision is made:
     - **Right after the user speaks** (43–46% of decisions), it can act on 18–23% of them at τ = 0.8, with 92–99% agreement. Common openings like "identify the user" are predictable.
     - **Right after a tool returns** (54–57% of decisions), it can act on only 6–8%.
   - Whether a run continues, and with which tool, depends on what the tool returned. The habit cannot see that; a System-One question over the tool output can. This is the strongest argument in the data for putting Jev inside flows.
4. **Behavior transfers across models.**
   - A habit learned from one model predicts another's held-out behavior within about 3 points of top-1 (airline: 50% against 53%) to 7 points (retail: 55% against 61%) of that model's own habit.
   - That supports the transfer-first plan: compile from one model's traces, and run with another.
5. **Code features help a little; naming the intent helps where the data support it.**
   - Enum-like fields read from JSON tool outputs are kept only if they raise the likelihood of *held-out tasks* (cross-validation grouped by task).
   - That grouping is essential. Each task repeats across trials and models, so in-sample evidence happily picks fields that merely identify the task (a user's city or state). The grouped test rejects them.
   - What survives is small but sensible:
     - retail: how many orders the user has, and how many items a write touched;
     - airline: membership tier, and insurance on a flight change.
   - Then the intent (the set of write tools the episode goes on to call, standing in for what the LLM states when it calls a macro-tool) is layered on top. It uses a two-level Bayesian back-off, so rare intents fall back to the shared model.
   - At τ = 0.8, the share of decisions the habit could take:
     - retail rises from 15% (sequence only) to 18% (plus code features) to 24% (plus intent), with agreement 87%, 86%, 82%;
     - airline stays near 12%, because 30 training tasks spread over 19 intents is too little data.
   - Folding the intent naively into every context *hurt* (retail 1.80 → 1.85 bits). Structure matters as much as information.
6. **Most decisions still need content-aware judgment.**
   - Even with code features and a named intent, three quarters of decisions sit below τ = 0.8.
   - The habit agrees with the agent 82–97% of the time on the decisions it can take, but the Phase 2 gate (≤ 1 point of success lost) needs near-perfect agreement on anything it automates. So the habit alone can safely take roughly 10–15% of decisions (the τ = 0.9 column).
   - The rest is what Phase 0b must measure Jev on.
7. **Projection: the gate needs Jev to be nearly perfect, and it depends on the agent model.** Held-out episodes were replayed through `plan_*` flows driven by that habit.
   - **Habit alone saves almost nothing:** at most 1.2% of LLM turns. Nearly every run contains one decision it can't make confidently, so the run doesn't collapse.
   - **With a System-One model that always agrees with the agent** (the upper bound Phase 0b can find), savings reach 22.0% (retail) and 20.6% (airline), against ceilings of 22.9% and 23.9%. That takes about 7 System-One decisions per episode.
   - **Pooled, the 20% gate is cleared only narrowly. By model, it splits on how the agent calls tools:**

     | Agent model | Parallel tool turns (retail / airline) | Turns saved, retail | Turns saved, airline |
     |---|---|---|---|
     | Claude 3.7 Sonnet | 0% / 0% | 32.7% | 36.6% |
     | o4-mini | 0% / 0% | 22.6% | 24.5% |
     | GPT-4.1 | 20% / 22% | 19.4% | 10.9% |
     | GPT-4.1-mini | 20% / 24% | 12.0% | 6.6% |
     | GLM-5 *(transfer target)* | 27% / 45% | 28.5% | 15.4% |

   - A model that issues independent reads in parallel has already collapsed part of each run itself, so less is left for a macro-tool. For GLM-5 on airline the ceiling is 18.9%, so even a perfect System-One model cannot reach the gate there. On retail it saves 28.5%.
   - So the gate should be judged per agent model, and the parallel-call rate of GLM and MiniMax is the first thing to measure live.
   - **Transfer to GLM-5 holds.** Habits from the four older models predict GLM-5's held-out actions at 56–63% top-1 in retail (its own habit: 67%) and 48–57% in airline (its own: 57%).
8. **Tokens and dollars fall faster than turns.** From the usage and cost τ²-bench recorded for every LLM call, under the same projection:
   - Input tokens fall 26% (retail) and 28% (airline); output tokens fall 19% and 25%.
     - Input falls faster than turns because the removed turns come late, with long prompts, and a collapsed run's intermediate tool outputs no longer ride along in every later prompt.
     - Output falls slower, because the removed turns are short tool calls.
   - Dollars fall 32% and 38%, but the pooled figure is mostly Claude 3.7 Sonnet: 72–75% of the recorded spend.
     - Its runs were billed at list price, without prompt caching.
     - The OpenAI runs were billed at 48–66% of list, thanks to automatic caching.
   - By model, dollars fall 37–43% (Claude 3.7 Sonnet), 23–32% (o4-mini), 15–17% (GPT-4.1) and 10–13% (GPT-4.1-mini).
   - GLM-5's run was self-hosted, so it has no costs. Its input tokens fall 29% (retail) and 18% (airline).
9. **"Habit only where validated" turns the habit into a stopping rule.**
   - A context is validated when the habit's top option matched the agent in at least 99% of at least 20 decisions, under 5-fold cross-validation grouped by task. Only 3 contexts in retail and 1 in airline qualify.
   - Every one of them says "respond": hand back to the LLM. So under this rule the habit never picks a tool. Every next step inside a run, and every closed-set argument, falls to the System-One model: about 7.3–7.6 decisions per episode. Jev's accuracy on them decides the gate.
   - **It is safe.** Handing back too early costs one LLM turn and has no side effect; picking another tool, or carrying on when the agent stopped, is the real risk.
     - Counted that way, the validated habit makes no risky decisions on held-out tasks in either domain.
     - A global threshold of τ = 0.95 makes 1.9 risky decisions per 100 retail episodes, plus 5.6 early hand-backs. The earlier draft of this page counted both together as 7.5%.
   - **Validation can overstate.** One retail context was 100% of 38 under cross-validation but 72.8% of 81 on the held-out tasks: after `get_user_details` (one order) and `get_order_details`, test-split agents often went on to look up products.
     - Because that call was "respond", the misses were safe hand-backs.
     - It still means a validated context must be monitored in production, not trusted once.
10. **Confirmation before writes is mostly followed, but not always.**
   - The user's latest message before a write contains "yes" 87–93% of the time in retail and 66–85% in airline (GLM-5, with a different user simulator: 97%).
   - Counting assent phrases like "go ahead", it is 91–96% and 85–98%.
   - The gap between the two proxies is what a Jev `Noul` ("did the user explicitly confirm this action?") should settle. What remains after that is a baseline violation rate that plan/commit should drive to zero.

## Caveats

- **Old models.** The published baselines are mid-2025 models. Our live runs (GLM, MiniMax) will differ. GLM-5 narrows the gap but changes two things at once: a different user simulator (GPT-5.2) and a newer τ²-bench (1.0.1). Its episodes are much shorter (7–9 LLM turns against 10–14).
- **Agreement is not correctness.** It measures how often the habit matches the agent, and the agent fails 21–50% of tasks.
- **Headroom is an upper bound.** It assumes the agent adopts macro-tools, and that every branch inside a run resolves without a pause.
- **Dollars depend on the billing.** Removed turns are priced at their recorded cost. The context reduction is priced at each model's effective input price, fitted to its recorded costs, so it inherits whatever caching the original run had.
- **Provenance and confirmation are text-matching heuristics.** Both are labeled as such in the report.

## Next: Phase 0b (replayed shadow mode)

**Target.** The residual after code features and the named intent: about 76% of retail decisions and 88% of airline decisions sit below τ = 0.8. Under validated arbitration, that is every in-flow decision: about 7 per episode.


- **What.** Ask Jev at each of the 12,861 held-out decisions (7,115 of them right after a tool returned). Use a `Choice` over the exposed tools plus "respond"; the state is the last user message, the last tool output, and recent actions.
- **Measure.**
  - Agreement with the agent, and calibration.
  - Arbitration: habit first, Jev where the habit is unsure.
  - The four in-flow roles, on the decisions where each one applies.
- **Cost.** About $1.60 at 3k tokens per call, cached so it is paid for once.

#### Projection: what macro-tools would save on held-out tasks

Each run of consecutive tool calls is replayed as one `plan_*` call driven by the habit above (code features + named intent). Where the habit may not act, the decision goes either to the LLM (a pause, one turn) or to a System-One model assumed to agree with the agent (the upper bound Phase 0b will test). Generated arguments always pause. Collapsing every run to one call would save 22.9% of LLM turns (the ceiling).

The habit may act either wherever its top option clears a threshold (with at least 5 training observations), or only in *validated* contexts: those where its top option matched the agent in at least 99% of at least 20 decisions under 5-fold cross-validation grouped by task. A habit that hands back too early is safe: the LLM takes the step, at the cost of one turn. A habit that picks another tool, or carries on when the agent stopped, is the risk.

### Reading the numbers

- **Bits/step** is the cross-entropy of the agent's actual next action under the habit: 0 means perfectly predictable. **Top-1** is how often the habit's first choice is what the agent did. Actions are tools plus `respond` (a message to the user).
- **Coverage @ τ** is the share of held-out decisions where the habit's top option has probability ≥ τ; **agree** is how often that option matched the agent there. Agreeing with the agent is not the same as being right: the agent fails some tasks.
- **Macro-tool headroom** is Σ(n − 1) over runs of n consecutive tool-calling LLM turns, as a share of all LLM turns: an upper bound on the turns `plan_*` macro-tools could remove.
- **Argument provenance** looks each argument value up, verbatim and lower-cased, in what the user had said and in earlier tool outputs. *Generated* values appear in neither, so the agent had to produce them. *Short* values (< 3 characters) are not attributed.
- **Code features** are enum-like fields read from JSON tool outputs by code, kept only if they raise the likelihood of *held-out tasks*: a field that merely identifies the task (a user's city) looks predictive on repeated trials and is rejected.
- **Writes after "yes" / any assent** look at the user's most recent message before each write call: the strict proxy needs the word "yes", the lenient one also accepts phrases like "go ahead" or "proceed". The true confirmation rate lies between them; the System-One question "did the user explicitly confirm?" will measure it.
