# Compile the skeleton, not the conversation

*A literature review, 2026-09-26: can recorded agent traces be compiled once into workflows that run with little or no frontier model? It was put together from seven research passes (agent workflow and skill induction, trace compilation, process mining and RPA, dialogue flow induction, industry platforms, theory, and stretto's own results), each claim linked to its source. Most of the work it reviews is 2025–2026 preprints; read its figures as orders of magnitude. [The anatomy of τ²-bench episodes](../results/anatomy-2026-09-26.md) measures the number it found missing.*

Compiling τ²-bench retail and airline traces once into workflows that then run with little or no frontier LLM is feasible only for the part stretto already automates: the read-only skeleton of lookups and the argument data flow between tool outputs. Neither the prior art nor stretto's own measurements support compiling the branch policy or the writes. Stretto's TraceCompiler-like arm, which follows only unbranched paths and hands every branch back, saves **1.7% of LLM turns in retail and 0% in airline** on recorded episodes where the current read-only flow saves 21.2% and 6.5% (and 25.5% live over 80 paired tasks); the best content-aware branch decider agrees with the agent **79–81%** of the time where flows that write need about 99%; and even a perfect decider allowed to write raises the turn ceiling by **under 3 points**, because about three quarters of LLM turns either answer the customer or make the first call after the customer speaks. None of the reviewed work compiles τ-bench or τ²-bench retail or airline traces into executable workflows and reports pass^k: the closest system, TraceCompiler, ran one intent end to end by hand and declined another; LLM-free replay with near-total savings appears only for repetitive, branch-free or execution-verified tasks; and the large τ² pass-rate gains came from graphs compiled from the written policy, with an LLM still working inside every node. The evidence supports a hybrid that compiles control from the policy and data flow from the traces once, keeps branch choices probabilistic and cheap to get wrong, leaves writes to the LLM or the customer behind deterministic guards and confirmation checks, moves residual judgment to a cheaper model rather than to code, and re-audits per serving agent and harness, because a trace records one model's habit in one harness rather than the task's structure. What remains to win is dollars per turn and pass^k reliability, not turn count.

## Prior art removes the LLM only where work repeats without branching

Trace reuse takes several forms, and they differ mainly in who decides at run time. Textual workflow memory puts induced procedures into the prompt, so an LLM still acts at every step. In-loop prediction and speculation execute or pre-execute predicted calls while the LLM stays authoritative. Executable skills run their bodies without an LLM but leave it to choose which skill to call and with what arguments. Only whole-workflow compile-and-replay runs with no LLM when a stored workflow matches the task, falling back to an agent when it does not, and that is the regime the question asks about. Most of this literature is 2025–2026 preprints, several from small teams or from vendors selling the approach, so the figures are best read as orders of magnitude. The table sets each family's best reported effect beside the closest thing it has to a τ²-bench test; the text that follows cites each figure.

| Family | Systems | LLM at run time | Best reported effect | Closest test to τ²-bench |
|---|---|---|---|---|
| Whole-workflow compile and replay | LOOP, Compiled AI, PreAct | None when the workflow matches; agent otherwise | 93.3–99.98% fewer tokens; 8.5–13× faster replay | None (periodic jobs, a function-calling benchmark, GUI tasks) |
| Trace compiler with argument provenance | TraceCompiler | Residual decision, LLM and human nodes | 34 calls → 11 on one intent; a second intent declined | AppWorld and T1 |
| Executable skills | ASI, WebXSkill, NSI | Chooses the skill and its arguments | 23.5% relative success gain and 10.7–15.3% fewer steps (ASI) | WebArena |
| In-loop habit execution | AutoTool, stretto's D0 | Authoritative except for predicted calls | 15–25% fewer LLM calls (AutoTool); 25.5% fewer turns live (stretto) | stretto: τ² retail and airline |
| Speculation with verification | Speculative Actions, SMC | Authoritative at every step | Up to 20% lower latency; SMC −18.6% | τ-bench retail; τ² telecom |
| Plan caching with a small adapter | Agentic Plan Caching | Small model when a cached plan matches | −50.3% cost at 96.6% of accuracy | GAIA, FinanceBench |
| Policy-compiled graphs | STAGE, PolicyGuide | At every node, or as a verifier | Mean τ² Pass⁴ 0.42 → 0.62 (PolicyGuide) | τ² retail, airline, telecom |
| Textual workflow memory | AWM, WISE-Flow | At every step | τ² telecom pass¹ 0.462 → 0.564 (WISE-Flow) | τ² telecom |

### Savings stay near 25% unless the task repeats exactly

The near-total savings in this literature all come from tasks that recur without branching. **LOOP** records the tool calls of a first LLM-guided run of a periodic job, extracts parameterized, **branch-free** templates and bypasses the LLM on later runs, cutting monthly tokens by 93.3–99.98% ([LOOP](https://arxiv.org/abs/2605.14237)). **Compiled AI** has an LLM write code once and then executes with zero model tokens, completing 96% of function-calling tasks and breaking even after about 17 transactions ([Compiled AI](https://arxiv.org/abs/2604.05150)). **PreAct** compiles a successful computer-use run into a state machine that replays 8.5–13× faster, checks the screen before each step, returns control to the agent "the moment something is off", and stores a program only after an independent evaluator confirms it from a clean state ([PreAct](https://arxiv.org/abs/2606.17929)). Vendor replay tools report the same shape without success-rate data: Skyvern's cached Playwright scripts run 2.3× faster and 2.7× cheaper than its agent ([Skyvern](https://www.skyvern.com/blog/asking-ai-to-build-scrapers-should-be-easy-right/)).

Everything conversational or branching lands near stretto's current figure. **AutoTool**, the closest published analogue of stretto's habit, mines a tool-transition graph with parameter-dependency edges, executes a predicted call only when every required parameter can be filled, and cuts LLM calls by 15–25% with such calls capped at 30% of actions; a trigram baseline that reuses its parameter filler nearly ties it (ScienceWorld progress 0.6476 against 0.6698), which suggests the argument filler, not the transition graph, carries the value ([AutoTool](https://arxiv.org/pdf/2511.14650)). Programmatic web skills cut steps by 10.7–15.3% (ASI, alongside a 23.5% relative success gain) and 21.3–27.0% (WALT) ([ASI](https://arxiv.org/html/2504.06821v2); [WALT](https://arxiv.org/html/2510.01524v1)). Speculative Actions predicts **22–38% of τ-bench retail API calls** for up to 20% lower latency, and limits speculation to actions that forking, snapshot restoration or repair can undo ([Speculative Actions](https://arxiv.org/html/2510.04371)). Agentic Plan Caching cuts cost by 50.31% while keeping 96.61% of optimal accuracy, but it gets there by letting a small model adapt cached plan templates, not by removing the model ([APC](https://arxiv.org/pdf/2506.14852)).

Speculative Macro Commit is the one system that skips actor LLM calls with multi-step macros mined from τ² traces, and it shows what verification buys ([SMC](https://arxiv.org/pdf/2609.03236)). On τ² telecom it cut latency by 18.59% with outcomes identical to sequential execution, yet a macro-library match alone reproduced the exact future steps only **34.6%** of the time. Executing the draft and verifying its first ("anchor") call raised that to 87.9%, and a depth guard to 90.4%; committing without online checks dropped accuracy from 99.52% to 96.48%; and the same macros, registered as tools, were "almost never" chosen by the actor. Multi-step prediction decays fast in general: AOSpec's action-prediction accuracy falls from 20.9% at one step to 2.4% at three and 1.2% at five ([AOSpec](https://arxiv.org/html/2608.00881)).

### The one tool-trace compiler shows both the method and its limits

**TraceCompiler** is the only reviewed system that compiles multi-turn API-agent traces into executable workflows with explicit argument provenance and write handling ([TraceCompiler](https://arxiv.org/html/2608.02680v1)). It clusters conversations into intents with a floor of five traces per cluster, strips retries and schema lookups, and admits a dependency edge only when a consumer argument holds a value "attributable uniquely to an earlier producer", marking anything ambiguous as "suspected". It then classes each binding as constant, user input, copy, deterministic transform or `llm_or_dynamic`, and only the last calls a model at run time. The provenance rule recovers dependencies at **0.928 precision and 0.943 recall**, where a Heuristics-Miner-style count of which call directly follows which scores **0.712 F1** ([TraceCompiler](https://arxiv.org/abs/2608.02680)). On AppWorld's Venmo money-request intent, 34 recorded calls compiled to 11 run-time calls with one residual LLM node that chooses the recipient; under leave-one-out the workflow passed 15 of 21 state tests, and the failing fold escalated "because its required branch was never observed". A Spotify/Todoist intent was **declined** because an irreversible side effect was under-determined.

The authors state the gaps themselves. No runtime exists for the workflow IR, so the Venmo result was hand-transcribed into simulator calls. No compile-or-decline rate is reported across 56 scenarios, although "that rate—not either case study—is the adoption-relevant number". Routing accuracy and compile cost are unmeasured, and all traces come from one ReAct agent, which leaves an "unexamined premise—that observational traces are evidence about *task* structure rather than one agent's habits" ([TraceCompiler](https://arxiv.org/html/2608.02680v1)). Its evidence shows that compile-once execution can work on one intent, not how often it works.

Robotic process mining reached the same design years earlier. It calls a routine automatable when "the value of each parameter of each action can be computed from the values of parameters of previous actions", almost exactly stretto's condition for auto-executing a lookup, and it rejected process-discovery algorithms that generalise beyond the log because "automating a sequence of actions that has never been observed is risky" ([Bosco et al.](https://lepo.it.da.ut.ee/~dumas/pubs/rpadiscovery.pdf)). On synthetic and lab logs it detects automatable actions at F-scores of 0.84–1.00, but on one of its two real employee logs "our approach could not discover any correct routine"; it cannot handle conditional transformations, loops over line items or values the user reads rather than copies; and no paper reports whether the synthesised scripts run correctly end to end ([Leno et al.](https://arxiv.org/abs/2106.13446)). Industry practice stopped at ranked candidate lists for human bot-builders, and scale stayed rare: in Deloitte's 2018 survey only 4% of organisations ran more than 50 robots, and process fragmentation was the top barrier at 32% ([Legal IT Insider](https://legaltechnology.com/deloitte-rpa-report-admits-surprise-at-lack-of-vision-and-it-readiness/)).

The controlled comparisons that exist reward verification and explicit branches, not replay. AWM's workflows offered as fixed-sequence callable actions were used in only **18.5%** of tasks and scored lower task success than the same workflows given as text (3.6 against 4.8 on Mind2Web) ([AWM](https://arxiv.org/html/2409.07429)). Removing execution verification from WebXSkill cost **14.3 points** on WebArena ([WebXSkill](https://arxiv.org/html/2604.13318v2)). NSI, which lifts traces into programs with first-order-logic branch predicates and variables bound from state, beat both text workflows and straight-line skills, scoring 44.5% on WebShop against 30.0% for AWM and 7.5% for ASI ([NSI](https://arxiv.org/html/2605.01293)). Read together, the systems converge on one recipe: induce only from verified successes, cluster by intent, strip accidental calls, admit data-flow edges by unique provenance rather than by order, represent branches as guards over structured state and abstain where the deciding information is not logged, verify each artifact by execution before storing it, check preconditions at every run-time step and hand back on mismatch, gate irreversible writes, and version artifacts against drift. No system following that recipe runs a branching, conversational task without an LLM.

### τ²-bench gains came from policy graphs, not traces

The largest reported improvements on τ²-bench come from compiling the written policy, not the traces, and an LLM still works inside every node. **STAGE** decomposes the policy into a frozen graph in which "the LLM owns local meaning, while code owns control". Its retail graph has **5 nodes and 1 decision** and its telecom graph 13 nodes and 2 decisions; it lifts retail Pass³ by 15–25 points (DeepSeek V4 Flash 10.0 → 35.0) and telecom Pass³ by up to 55 points (GPT-5.6 Luna 32.5 → 87.5), while measuring neither cost nor airline and warning that "construction or validation errors can systematically enforce an incorrect procedure" ([STAGE](https://arxiv.org/html/2608.22538)).

**PolicyGuide** compiles each domain's policy into a workflow graph once and adds a verifier at user-turn boundaries. With GPT-5.4, mean Pass⁴ rises from 0.42 to 0.62, driven by telecom (+0.421, 95% CI 0.316–0.526) and airline (0.460 → 0.620), while retail moves +0.018 (−0.070 to +0.105), which is not significant. The frozen airline graph carries over to Claude Sonnet 4.6 and Gemini 2.5 Pro, and the verifier adds 7.4–11.5 LLM calls and $0.34–0.56 per task ([PolicyGuide](https://arxiv.org/html/2608.19861)). PolicyGuide's own count of requirements explains the retail result: 27 of retail's 28 requirements are flat process-level rules, only one is an ordered workflow, and 13 can be checked only in the dialogue ([PolicyGuide](https://arxiv.org/abs/2608.19861)), whereas telecom's policy is written as a troubleshooting flowchart ([τ²-bench](https://arxiv.org/abs/2506.07982)).

Two other results fit the pattern. XFlow's compiled protocol raises compliance to 100% in retail and airline while pass^1 barely moves, so compliance and success diverge ([XFlow](https://arxiv.org/abs/2606.14790)). WISE-Flow, the only trace-induced τ² method, uses induced workflows only as prompt guidance: Claude 3.7 Sonnet's telecom pass^1 rises from 0.462 to 0.564, Qwen3-235B's does not move, and no cost is logged ([WISE-Flow](https://arxiv.org/pdf/2601.08158)).

Dialogue-flow induction from transcripts recovers happy paths, not executable programs. GPT-4-induced flows covered only **31.6–43.0% of held-out transitions** and were never used to run a bot ([Agrawal et al.](https://arxiv.org/abs/2408.01623)). ServiceNow's workflow discovery on ABCD matched the full action-and-slot workflow exactly in **44.1–55.7%** of dialogues even with a closed action list, with slot values the main error ([Hattami et al.](https://arxiv.org/abs/2205.11690)), and NVIDIA's extracted policies "should not be used to implement any TODS without careful inspection by a conversation designer or domain expert" ([Sreedhar et al.](https://arxiv.org/abs/2406.15214)). The flows that clearly help are hand-authored: in Rasa CALM an LLM emits commands and flows run the business logic deterministically, and it passed 95.8% of tests against 47.9% for an intent-classifier bot ([Rasa CALM](https://arxiv.org/abs/2402.12234)). Flows also collapse when users leave them: with out-of-workflow queries on FlowAgent's in-house set, GPT-4o ReAct's session success fell from 62.50 to 18.03 and FlowAgent's own from 67.72 to 32.01 ([FlowAgent](https://arxiv.org/abs/2502.14345)).

### Vendors automate authoring but keep the LLM and a human gate

Production platforms share one runtime contract: an LLM maps free text to a small set of typed actions and writes the replies, while a deterministic layer owns business logic, tool visibility and state. Salesforce's Agent Script runs deterministic logic "as code with no LLM involvement", and its `available when` gate "removes actions from the LLM's tool list entirely" ([Salesforce Architects](https://architect.salesforce.com/docs/architect/fundamentals/guide/hybrid-reasoning-agentforce-builder-agent-script)). Rasa, Google, Microsoft, Decagon, Intercom and Parlant draw the same line, and none documents a live conversation with no LLM at all. Sierra, which built τ-bench and τ²-bench, describes its customer journeys as "Goals and guardrails, not the sequence of steps" ([Cheeky Pint](https://cheekypint.substack.com/p/bret-taylor-of-sierra-on-ai-agents)). Rasa's comparison with a LangGraph assistant is the clearest cost case for taking business logic away from the LLM, at $0.04 against $0.10 per message and 2.08 s against 7.4 s, but it covers five conversations and was run by the vendor ([Rasa](https://rasa.com/blog/cutting-ai-assistant-costs-the-power-of-enhancing-llms-with-business)).

Automatic authoring from logs has arrived, but its output is a hybrid spec that a human approves. Decagon's Duet analyses "real customer transcripts" to generate procedures, and its Autopilot tests each proposed change against the conversation that surfaced it and a golden set of hundreds, with every change requiring human approval ([Duet](https://decagon.ai/blog/introducing-duet); [Autopilot](https://decagon.ai/blog/autopilot)); Sierra's Ghostwriter builds journeys from SOPs and transcripts and shows the result for review before it ships ([Ghostwriter](https://sierra.ai/product/ghostwriter)). The one external quality number is sobering. On Sierra's Hyper-τ-bench, Claude Opus 5 building a customer-service agent alone from a simulated business's records passed **23.9%** of held-out τ-style tasks, against **82.2%** when paired with an engineer, and 92% of solo builds were a single LLM loop ([Hyper-τ-bench](https://sierra.ai/blog/hyper-t-bench-evaluating-agents-that-build-agents)). muscle-mem, a library that replayed agents' tool-call traces deterministically, drew "seemingly no users"; its author blamed "rigid workflow definitions requiring advance knowledge of all workflows", "recording wrong signals (tool traces rather than LLM context windows)" and "inability to handle dynamic data variations" ([Butter](https://blog.butter.dev/muscle-mem-as-a-proxy)).

## Branch points, argument choices and writes break every compiler

### Traces show the path taken, never the paths that would have worked

Learning a workflow from successful traces means learning from positive examples only, and theory is blunt about that. Regular languages cannot be identified in the limit from positive examples alone ([Gold 1967](https://en.wikipedia.org/wiki/Language_identification_in_the_limit)); finding the smallest automaton consistent with the data is NP-complete ([Gold 1978](https://www.sciencedirect.com/science/article/pii/S0019995878905624)); and sparse state-merging problems stayed unsolved in the Abbadingo competition, including a 125-state target with 4,382 training strings ([Abbadingo](http://abbadingo.cs.nuim.ie/data-sets.html)). Probabilistic automata can be learned with high probability from samples, but the sample size grows with how hard states are to tell apart ([Clark & Thollard](https://www.jmlr.org/papers/v5/clark04a.html)), so a rarely visited branch needs many traces; a missing branch is exactly what sank TraceCompiler's failing fold. Its authors put the limit plainly: "Traces record which path an agent took, not which would have worked, so observational data bounds claims about necessity as tightly as claims about dependency" ([TraceCompiler](https://arxiv.org/abs/2608.02680)).

Programming by example makes few-shot synthesis work with three things: a narrow language, a learned ranking over the up to 10^30 programs consistent with the examples, and a user who answers clarifying questions ([Mayer et al.](https://alexpolozov.com/papers/uist2015-disambiguation.pdf)). Learned ranking alone cut the examples needed from 4.17 to 1.48 ([Singh & Gulwani](https://www.microsoft.com/en-us/research/publication/predicting-a-correct-program-in-programming-by-example/)). A trace compiler has the narrow language in its MCP tool schemas and can borrow a ranking from the written policy, but it has no user at compile time. The principled substitute is active querying, probing the environment to test paths the traces never showed: τ²'s deterministic database can answer the tool side of "would this path pass?", but the customer side depends on a simulator that makes errors in 40–47% of annotated retail and airline conversations ([τ²-bench](https://arxiv.org/abs/2506.07982)).

Branch conditions can be learned only when the facts that decide them are logged as structured data. Decision mining turns each branch point into a classifier and assumes "all factors influencing decisions are recorded"; on real logs some branch points yielded no rule at all, and a standard decision tree learned the condition `false` for a minority "Intensive care" branch, erasing it ([Mannhardt et al.](https://www.math.unipd.it/~deleoni/documenti/M_dL_R_vdA@CAISE16.pdf)). Inferred state machines with data are "only partial", and when a system reacts to outside input, that input "will still be required" at run time ([Walkinshaw & Hall](https://eprints.whiterose.ac.uk/id/eprint/127869/1/ICSME2016FinalSubmission.pdf)). In τ², the outside input is the customer's words: which item, which reason, whether they said yes. Where the facts are logged, inferred conditions still need checking, since Daikon's inferred invariants recover about 60% of programmer-written contracts and about a third of what it generates is wrong or irrelevant ([Polikarpova et al.](https://cseweb.ucsd.edu/~npolikarpova/publications/issta09.pdf)). Handing the modelling to an LLM does not remove the problem: in a controlled study, LLMs asked to model processes overrode explicit evidence with generalized knowledge ([Kourani et al.](https://arxiv.org/abs/2509.15336)).

### Values vary, writes cannot be undone, and tools drift

Agents repeat their tool sequences far more reliably than their arguments. Across 1,140 traces, tool-sequence similarity averaged 0.87 but argument consistency only 0.69, and natural-language outputs matched exactly less than 5% of the time ([Yagubyan](https://arxiv.org/html/2605.28840)). In τ-bench retail, about **55%** of gpt-4o's agent failures were wrong arguments or information, 25% wrong policy decisions and 19% partial handling of compound requests ([τ-bench](https://arxiv.org/html/2406.12045v1)). A compiled skeleton therefore captures the reliable part and leaves the error-prone part, choosing values, where it was.

Writes are where every careful system stops. TraceCompiler emits a human node "when a node with an irreversible external effect has a binding the analysis could not resolve" and declines to compile at all when a side effect is under-determined ([TraceCompiler](https://arxiv.org/pdf/2608.02680)), and Speculative Actions restricts speculation to reversible actions ([Speculative Actions](https://arxiv.org/html/2510.04371)). Replayed scripts fail silently: in CoScripter "one wrong prediction in the middle of the process usually leads the entire script astray", while "the system says it has completed the script successfully" ([Lau](https://ojs.aaai.org/aimagazine/index.php/aimagazine/article/view/2262)). Replay tooling adds its own silent failures, as when Stagehand's agent cache skipped custom tool calls entirely on a cache hit ([Stagehand #1558](https://github.com/browserbase/stagehand/issues/1558)). In τ²-bench, cancellations, exchanges, returns and rebookings change the database state that scoring checks at the end, and the tools offer no undo.

Conversation and the long tail undo fixed paths. In real chatbot logs, 47.9–73.1% of queries fell outside the intents the bots were designed for ([HINT3](https://arxiv.org/html/2009.13833v2)); at fine granularity "most traces are unique" ([van der Aalst](https://www.scitepress.org/Papers/2020/99792/99792.pdf)); and practitioners automate about 70% of a process because the remaining exceptions "can double the time to deliver" ([EY](https://eyfs.ie/wp-content/uploads/2016/11/ey-get-ready-for-robots.pdf)). The traces themselves are contaminated. gpt-4o's retail pass^8 falls below 25% ([τ-bench](https://arxiv.org/abs/2406.12045)), τ²'s simulated customers make critical errors in 12–13% of retail and airline conversations ([τ²-bench](https://arxiv.org/abs/2506.07982)), and removing the written policy drops gpt-4o's airline pass^1 from 33.2 to 10.8 ([τ-bench](https://arxiv.org/html/2406.12045v1)), so rules mined from what agents did encode their habits and mistakes unless they are checked against the policy.

Drift and routing weigh against "once" as well. Only 44.4% of ToolBench API calls succeeded and 55.6% of its tools changed status over time ([StableToolBench](https://arxiv.org/html/2403.07714v5)), and compiling away schema lookups "converts an API change from a self-healing event into a silent-wrong-behavior one" ([TraceCompiler](https://arxiv.org/pdf/2608.02680)). Macros help only where they fit: options can slow learning even when the agent keeps direct access to primitive actions ([Jong et al.](https://www.cs.utexas.edu/~pstone/Papers/bib2html-links/AAMAS08-jong.pdf)), and curated agent skills hurt 16 of 84 SkillsBench tasks while self-generated skills lost 1.3 points on average ([SkillsBench](https://huggingface.co/papers/2602.12670)). Every branch that depends on unstructured input becomes a choice between deciding cheaply and deferring, and at high accuracy a cheap component typically takes half to 60% of decisions: a trained calibrator answered 56% of questions at 80% accuracy under domain shift ([Kamath et al.](https://arxiv.org/abs/2006.09462)), and requiring agreement across agent runs gave 54–62% coverage at 87–88% accuracy ([Mehta](https://arxiv.org/abs/2602.11619)). If a workflow has three such decisions, each handled cheaply 60% of the time and independently, only about 22% of conversations finish without the expensive model (0.6³). No source reports how many decisions a cheap component can take at the ~99% accuracy that irreversible writes demand.

## Stretto's retreat from whole workflows was measured, not forced

Stretto's own history is the most direct evidence on the question, because no reviewed external work compiles τ² retail or airline traces. RFC-001 began as a whole-workflow compiler. It would mine flows from traces and serve them as `plan_*`, `resume_*` and `commit_*` macro-tools, resolving each branch by the habit, then Jev (stretto's System-One model, TypeSafe's jev-1.13.0), then the LLM, then a person; free-text arguments would be bound by data flow, and `plan_*` would return the exact write calls for the customer to confirm and `commit_*` to replay ([RFC-001 §3.5](../rfc/001-habit-compiler.md)). Measurement pared this down to D0, a read-only continuation that makes the lookups likely enough after each agent call and hands back. The reasons were measured decision accuracy and measured small marginal value, not an implementation obstacle ([RFC-001 §3.13, §3.16](../rfc/001-habit-compiler.md); [design](../design.md)). D0 "adds no tools and changes no prompt, which sidesteps the adoption risk" that undermined SMC's tool-registered macros and AWM's workflow actions ([RFC-001 §3.14](../rfc/001-habit-compiler.md)).

The live evidence has clear limits. It covers τ² retail and airline only, with GLM-5.3 playing both agent and customer, scored on the database check alone, and every confirmation and match label comes from one annotator, the model that ran the analysis ([paired run](../results/paired-2026-09-25.md); [roadmap](../roadmap.md)).

The table answers the "instead of" in the question. A workflow that runs deterministically wherever the traces show no branch saves almost nothing, because, in the arms report's words, "Branches are everywhere. Flows pay because they act on a probability, and a wrong read costs only a detour" ([arms](../results/arms-2026-09-24.md)). Letting a perfect decider also write raises the ceiling by only 0.5–2.9 points over reads alone, and naming flows and bundling writes are bounded at a few points more. Collapsing every run of tool calls into one call on held-out 2025 episodes is capped at 22.9% of turns in retail and 23.9% in airline ([Phase 0](../results/phase0-2026-09-23.md)), so the other three quarters of LLM turns either reply to the customer or make the first call after the customer speaks, and RFC-001 lists "Replacing the LLM for open-ended work" as a non-goal ([RFC-001 §2.4](../rfc/001-habit-compiler.md)).

What is left inside the tool steps is decision quality, not structure. On GLM-5's recorded test episodes, D0's rule projects **20.3%** of turns saved in retail and **7.1%** in airline, where a perfect decider restricted to reads reaches 28.2% and 14.9% on the same episodes ([RFC-001 §3.13–3.14](../rfc/001-habit-compiler.md); [goal-free](../results/phase0b-v2-goal-free-2026-09-24-summary.md)). Live, D0 cut turns by **25.5% (95% interval 20.5–30.4%)** and input tokens by 21.0%, 242 of its 259 lookups were ones the agent itself would have made, and the savings carried to Claude Haiku 4.5 as the agent (−18.6%) and to Claude Sonnet 5 as the simulated customer (−23.1%) ([paired run](../results/paired-2026-09-25.md); [RFC-001 §3.22](../rfc/001-habit-compiler.md)). The pass rate moved −1.25 points (−7.5 to +6.25), and at that disagreement rate bounding the loss within one point would take about **4,300 pairs** ([paired run](../results/paired-2026-09-25.md)). If read-only automation is that expensive to certify, write-bearing workflows are more expensive still.

### Decision accuracy plateaus near 80% against a 99% bar for writes

After a tool returns, which is 54–57% of decisions, a sequence-only habit is confident (above 0.8) on only 6–8% of them, because "Whether a run continues, and with which tool, depends on what the tool returned. The habit cannot see that"; even with code features and a named intent, three quarters of decisions stay below that confidence level ([Phase 0](../results/phase0-2026-09-23.md)). Content-aware deciding helps but plateaus. Zero-shot Jev agreed with the agent's next step 71.8% of the time with good calibration, an expected calibration error of about 0.06 ([Phase 0b](../results/phase0b-2026-09-23-summary.md)). The best arbiter, which combines the habit, Jev and three state predicates, reaches **80.5% in retail and 78.9% in airline** and is at least 0.99 sure on only 10.6% and 25.2% of decisions ([Phase 0b v2](../results/phase0b-v2-2026-09-23-summary.md)); in telecom it drops to 67.9%, where "The shipped arbiters do not carry to telecom" ([telecom](../results/telecom-2026-09-25.md)). The working paper states the bar plainly: "flows that also *write* need roughly 99%" ([working paper](../../site/index.html)).

An episode involves about 7.5 such decisions, so an 80% decider agreeing independently at each one would match the agent's whole episode only about 19% of the time (0.8^7.5). That is an illustration rather than a measurement, since decisions are correlated and agreement undercounts equally valid alternatives. The goal-free result sharpens the point. Stating the customer's goal added nothing to read-only decisions (retail 80.5% with or without it), because "The goal names the writes, and a read-only flow hands every write back" ([goal-free](../results/phase0b-v2-goal-free-2026-09-24-summary.md)). The decisions a write-bearing workflow needs are exactly the ones stretto stopped scoring after its first round of Jev questions. The arguments a workflow must fill split the same way, and the split sets the resolver for each slot.

Finding a value upstream is easy; choosing among several upstream candidates is not. Offered every read-only tool with arguments bound by name from the manifest, airline flows made 83 and 91 detours against 0 and 1, including a flight search from ORD to ORD, which is why the report concludes "Only traces teach a flow how to fill a lookup's arguments" ([manifest options](../results/manifest-options-2026-09-24.md)). Jev's record-matching failures are systematic: after "I'd like to return all of the items in that order", it gave each item a probability of only 0.42–0.46 ([matching](../results/matching-2026-09-24.md)). Since the agents themselves pick the expected record only 89.9% of the time, neither copying the traced agent's choice nor a System-One matcher comes near 99% on write slots with several candidates.

### Checking writes works better than making them

All of stretto's write-side results are gates, and the gates work. Its guards are 22 typed rules compiled from the written policy by an LLM, tested against traces and reviewed by a person; each passes, fails or returns "does not know" when a fact was never looked up. In airline they would refuse a write in **141 of 369 failed episodes (38%)** but in only 5 of 431 successful ones, each forbidden by τ²-bench's own task notes, while retail's tools already enforce most of their own policy ([guards](../results/guards-2026-09-24.md)). Policy-derived rules still need auditing against traces: one post-pilot rule change would have blocked a path that τ²-bench's task 32 expects, and was reverted before going live ([RFC-001 §3.15](../rfc/001-habit-compiler.md)). Live, the guards found nothing to refuse, because GLM-5.3 declined forbidden cancellations on its own, and the one failure was a net-price error no guard saw ([guards pilot](../results/pilot-guards-2026-09-24.md)).

The confirmation judge, which checks that the customer agreed to a write, refused none of 40 writes when enforced live; in logging mode it would have failed 4 of 38, two real lapses and two false alarms, and its second question ("had the agent proposed this change?") raised seven false alarms in eight flags ([judge live](../results/judge-live-2026-09-25.md)). The most promising write check is unbuilt. In a blind sample of 30 flagged writes, 16 were real lapses, and 7 of those were calls that differed from what the customer agreed to; stretto's own analysis notes that "a check that compares a call's arguments with the ids, items and amounts in the agent's last message could catch them directly", with no model at all ([second question](../results/confirm-second-2026-09-24.md)). The structural bound also holds against injection: "No answer can make a flow call a tool it was not compiled to call at that site, or a write" ([injection](../results/injection-2026-09-25.md)).

### A trace records one agent's habit in one harness

"Compile once" assumes the recorded behaviour is a property of the task, and stretto measured that it is not. GLM-5 issued parallel calls in 45% of airline tool turns in τ²-bench's harness, while GLM-5.3 in Claude Code did so in 3.8% ([RFC-001 §3.15](../rfc/001-habit-compiler.md)), and the share of turns that macro-tools could remove ranges from 11% to 50% across models, depending on how each batches calls ([Phase 0](../results/phase0-2026-09-23.md)). The airline flow's likeliest option matched GLM-5's actual step at only 64.5% of decisions, and 41.9% after a reservation read, against 85.9% in retail ([audit](../results/audit-2026-09-24.md)). Per-site thresholds found by search encode the searched agent's habit, so "A search runs on the sessions of the agent the flow will serve" ([search](../results/search-2026-09-25.md)); state predicates proposed by an LLM "fitted the agents the proposer read, and nothing more" ([RFC-001 §3.23](../rfc/001-habit-compiler.md)); and in telecom the retail and airline arbiters made 43.5–49.7% of the agent's next lookups against 74.7% for telecom's own ([telecom](../results/telecom-2026-09-25.md)). Validation has to count tasks, not decisions: an airline context validated at 100% of 28 decisions held for only 42.9% of 56 decisions on new tasks ([Phase 0](../results/phase0-2026-09-23.md)).

The good news is that structure is cheap to relearn. The options learned at each site contain the agent's actual next step in 99.1% of decisions ([Phase 0b v2 report](../results/phase0b-v2-2026-09-23-report.md)), and five of an agent's own sessions taught a habit exactly the lookups that the habit learned from four other agents made, on all ten live tasks ([cold start live](../results/cold-start-live-2026-09-25.md)). Traces also bound what a flow can reach, since "Jev chooses among what the traces offer; it cannot add to it" ([sweep](../results/sweep-2026-09-24.md)).

## Compile the skeleton once, gate the writes, re-audit per agent

The design the evidence supports follows the lesson in stretto's working paper, "design the action space so that the fast path's errors are cheap, then let it act on weaker evidence" ([working paper](../../site/index.html)), and adds the write gates and model routing that prior art and industry practice supply. **The compiled artifact should be a probabilistic program, not a deterministic script.** Stretto's flow IR already holds each run "as a program in fugue's format … with a decision site before each lookup and an outcome site after it", executed with `run_async` and audited with `ScoreGivenTrace` ([working paper §3.3](../../site/index.html); [design](../design.md)). A fixed structure with posteriors at its choice points lets one artifact serve audit, promotion, threshold search and counterfactual evaluation, which TraceCompiler's deterministic IR, still without a runtime, cannot do.

**Control should come from the policy, and data flow from the traces.** The policy supplies the small control graph (STAGE's retail graph has one decision), and for retail and airline most requirements are flat gates better written as typed guards than as sequences. The traces supply bindings, and TraceCompiler's uniqueness rule and binding classes would upgrade stretto's tool-and-JSON-path learner, because provenance beats order (0.928 precision and 0.943 recall against 0.712 F1) and the manifest cannot teach arguments. Nothing should run along a path the traces never showed, which is why robotic process mining prefers lossless automata to process miners that generalise beyond the log; process-mining tools belong in analysis, not in the compiler.

**Decide per step what to formalise, and keep checking.** SKILL.nb's "selective formalization", in which execution evidence decides which steps become code, kept 91.7% of initially successful tasks across re-executions, and its bounded repair cut post-repair regressions to 4.2% against 15–17% for baselines that keep workflows fixed ([SKILL.nb](https://arxiv.org/abs/2606.08049)). Stretto's per-site promotion is the same idea and kept 277 of 294 retail turns saved while cutting detours from 58 to 28 ([promotion](../results/promotion-2026-09-25.md)). The roadmap's hand-back when a session surprises the flow (#17), its drift alarms (#18) and contract checks on MCP tool schemas would catch the silent failures that TraceCompiler and Stagehand document ([roadmap](../roadmap.md)).

**Writes stay with the LLM or the customer and pass deterministic gates.** Typed guards over looked-up facts go in front, the confirmation judge's first question is enforced, the unbuilt argument-versus-proposal comparison is added, and a state check after each write keeps a CoScripter-style derailment from passing silently. A router of the kind Chen et al. evaluated on τ² retail and airline fits here, keeping routine sessions on the cheap path and sending operationally conflicted ones to a slower workflow that reconsiders before each write ([difficulty-routed control](https://arxiv.org/abs/2607.01426)). RFC-001's original plan/commit design, in which a flow proposes exact write calls for the customer to confirm, is the one write-automation path the evidence leaves open. It is untested and its turn value is small, since naming adds at most 1.9–7.9% and bundling 0.2–3.5%, so it should be judged on pass^k and policy compliance, not on turns.

**The real lever for "little frontier-LLM involvement" is which model runs the residual nodes, not their removal.** Agentic Plan Caching holds 96.61% of accuracy at half the cost with a small model adapting templates ([APC](https://arxiv.org/pdf/2506.14852)); Rasa runs its command generator on "smaller, fine-tuned models" ([Rasa CALM](https://rasa.com/docs/learn/concepts/calm/)); when decision trees are split into one small decision per node, the models tested in Arbor converge near 90% turn accuracy at 13.8× lower per-turn cost ([Arbor](https://arxiv.org/abs/2602.14643)); and 7B models fine-tuned on DFlow beat GPT-4 at predicting the next action ([DFlow](https://arxiv.org/abs/2410.14853)). The gains depend on model strength. Compiled SOP execution helps stronger models and harms weaker ones ([Compile, Then Page](https://arxiv.org/abs/2607.11346)), and Qwen3.5-9B did better reading WebXSkill's skills as guidance than executing them, 84.86% against 71.86% on WebVoyager ([WebXSkill](https://arxiv.org/html/2604.13318v2)). Stretto's own hint is encouraging but small: with Claude Haiku 4.5 as the agent, D0 saved 18.6% of turns and passes rose from 6 to 7 ([RFC-001 §3.22](../rfc/001-habit-compiler.md)). The experiment that tests the actual thesis is the roadmap's #8, flows and guards compiled from frontier-model traces serving a smaller agent, with deferral to the frontier model decided by a trained calibrator rather than raw confidence, since softmax scores are overconfident on unfamiliar inputs ([Kamath et al.](https://arxiv.org/abs/2006.09462)).

**Evaluation has to measure what no one has measured yet.** The missing numbers are distinct end-to-end paths per intent (stretto measures only next-step predictability and counts 37 retail and 19 airline write intents), decisions per intent that depend on the customer's words, binding agreement for write arguments, a compile-or-decline rate, and held-out pass^k of a compiled workflow against the free agent. Pass^k needs an ordered-trace audit beside the database check, since among telecom runs that passed on outcome PolicyGuide found only 17.5% of ReAct traces followed a valid process ([PolicyGuide](https://arxiv.org/html/2608.19861)). Deliberately corrupting parts of the flow, as AnyTOD did with its policy graphs, would measure what an imperfect compile costs ([AnyTOD](https://arxiv.org/abs/2212.09939)), and labels need an annotator other than the model that ran the analysis (#11). Because a one-point pass-rate bound needs thousands of pairs, "Simulation ranks; it does not certify" ([RFC-001 §3.7](../rfc/001-habit-compiler.md)), and shadow runs on live traffic and a canary, both still unbuilt, are the path to certification.

The strongest case for compiling more rests on reliability and real traffic, not turns. Free agents are inconsistent, with gpt-4o's retail pass^8 below 25%, and policy-compiled graphs lift τ² pass rates sharply where procedures are ordered, so a compiled layer can earn its keep through pass^k even when it saves no turns. And τ²'s 114 retail and 50 airline tasks were designed for coverage, not sampled from traffic; a production deployment with a dominant head of common cases would reward compiled paths more than the benchmark does, as in one public process log where four variants cover 88% of cases ([Ceravolo et al.](https://arxiv.org/pdf/2306.10341)). Both arguments favour compiling policy gates and frequent read skeletons, which the design above already does. Neither rescues compiled branch decisions or compiled writes: PolicyGuide's retail gain was not significant, STAGE warns that a construction error is enforced systematically, and stretto's System-One matcher picked records less accurately than the agent it would replace.

## Conclusion

The question sets a learned habit against workflows compiled once, but stretto's evidence dissolves that contrast. D0 already is a compiled workflow, a fugue program with fixed sites and learned choice points, and stretto's measured retreat from RFC-001's whole-workflow design is the only measurement in the reviewed literature of compiling τ² retail and airline traces. What the evidence shifts is the objective. Turn savings inside tool steps are nearly exhausted, so the remaining value lies in dollars per turn, won by handing bounded residual judgment to a cheaper model under calibrated deferral, and in pass^k, won by compiling the written policy into gates on writes. A whole-workflow compiler would spend its effort on the few points of turn headroom that remain and on writes, where a wrong decision costs the most and every measured decider is weakest.

The better model for "once" is profile-guided compilation, in which a compiler optimises a fixed program from a recorded execution profile. The program here is the policy's guards, the data-flow bindings and the set of lookups each site may make; it survives a change of agent and can be compiled once. The profile is the thresholds, arbiter weights, promotion lists and searched settings, which encode how one model batches, orders and binds calls in one harness and have to be regenerated for each deployment. Regeneration is cheap where stretto has tried it: its live cold-start runs rebuilt the habit from five of a new agent's sessions and borrowed an arbiter shipped for another domain ([cold start live](../results/cold-start-live-2026-09-25.md)). Seen that way, the experiments with the most upside are cheap and not yet run: the argument-versus-proposal check on writes, and flows compiled from frontier-model traces serving a smaller agent.
